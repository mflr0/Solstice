# Code of conduct

This code applies to everyone taking part in Solstice: issues, pull requests,
reviews, discussions and any other space of the project.

## Behaviour

- Be respectful. Criticise code and ideas, not the people behind them.
- Assume good faith. When you disagree, say why.
- Insults, harassment, discrimination, threats, sexual content and publishing
  someone's private information are not accepted.

## Contributions and AI tools

You may use AI tools to write code, tests or documentation. The project does
not care how a change was written. It cares about who submits it, and that
person is its author.

1. You understand what you submit. You can explain any line of your pull
   request, why it is there and how you tested it, without going back to the
   tool. Reviewers may ask. If you cannot answer, the pull request is closed.
2. You checked it. It builds, tests and linters pass, and you ran the change
   yourself. Generated code that nobody has run is not a contribution.
3. The description is true. It says what you actually changed and tested; no
   invented test results, no generated filler.
4. You have the right to submit it. Code copied from a project whose license
   does not allow it is refused, whether you or a tool copied it.
5. You answer for it. If a contribution turns out to be a problem (a bug, a
   security flaw, a license violation, malicious code), its author is held
   solely responsible. "The AI wrote it" is not an excuse: a tool is never a
   contributor.

You don't have to declare that you used an AI tool. The rules are the same
either way.

Being responsible does not mean being punished for every mistake:

- Bugs happen to everyone. You will be asked to help fix yours, nothing more.
- If you keep submitting code you do not understand or have not tested, your
  pull requests may be closed without review.
- Malicious code (malware, backdoors, data theft, a hidden or hijacked
  dependency) or a deliberately misleading change leads to a permanent ban,
  removal of your contributions and a report to GitHub, and to the
  authorities where the law calls for it.

## Reporting

Report a problem privately to a maintainer rather than in a public thread.
Reports are kept confidential.

## Enforcement

Maintainers decide what to do based on how serious the problem is: a
reminder, removal of the message or code concerned, a temporary ban or a
permanent ban.
